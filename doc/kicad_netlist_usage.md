# Exporting a KiCad Netlist

This document explains how to export a circuit described with cuprite_wire (`doc/circuits.md`) as a
KiCad 9 netlist (`.net`) for pcbnew. See `doc/dev/kicad_netlist_format.md` for the file format itself.
A complete example is in `examples/kicad_rc_filter.rs`
(`cargo run --example kicad_rc_filter > rc_filter.net`).

## 1. Pipeline

```rust
let netlist = circuit             // CircuitBuilder
    .build(&options)              // BuiltCircuit
    .to_netlist()?                // Netlist (doc/circuits.md)
    .to_kicad()?                  // KicadNetlist: KiCad information resolved and checked
    .with_source("my_board.rs");  // optional `source` in the `design` section
netlist.write(&mut file)?;        // or `netlist.to_string()`
```

`to_kicad()` returns `Err(CircuitErrors)` with all errors found (section 5).

## 2. KiCad information of parts

`Part::kicad()` returns the KiCad information of a part; `None` (the default) makes `to_kicad()`
fail with `KicadUnsupported`. Parts generated by `kicad_part!` fill it from the symbol and the
footprint (`doc/kicad_part_macro.md`). By hand:

```rust
fn kicad(&self) -> Option<KicadPartInfo> {
    Some(KicadPartInfo {
        footprint: Some("Resistor_SMD:R_0603_1608Metric".parse().unwrap()),
        pins: BTreeMap::from([
            ("1".into(), KicadPinInfo::new("1", None, PinType::Passive)),
            ("2".into(), KicadPinInfo::new("2", None, PinType::Passive)),
        ]),
        lib_source: Some("Device:R".parse().unwrap()),
        ..Default::default()   // fields, flags (dnp, exclude_from_bom, exclude_from_board)
    })
}
```

- `KicadPinInfo` gives the pad number (`pin` in the netlist), the pin name (`pinfunction`) and the
  electrical type (`pintype`). `KicadPartInfo::pins` needs exactly one entry per pin ID, and pads
  must be unique within a part.
- `LibId` (`Library:Name`) is checked when it is parsed or created with `LibId::new`.
- For hand-written parts, whether a pad number exists in the footprint is not checked (it would
  require reading the footprint libraries; `kicad_part!` does it). Use
  `tools/check_netlist_footprints.py` (`doc/dev/verifying.md`).

## 3. UUIDs

pcbnew matches footprints on the board to netlist components by UUID (`tstamps`), so the UUIDs
must not change between exports. cuprite_wire derives them (UUID v5) from the **hierarchical path
and the instance name** of each part (`doc/circuits.md` section 4), never from reference
designators or source locations. The `tstamps` of a `sheetpath` joins the UUIDs of the subcircuit
instances with `/`.

An automatic instance name changes when a part of the same kind is added before it, and so does
its UUID: give explicit names to parts whose placement you want to keep.

## 4. Output

- `components`: `ref`, `value` (`~` if empty), `footprint`, `fields` (if any), `libsource` (if
  set), value-less `property` flags (`exclude_from_board`, `exclude_from_bom`, `dnp`), `sheetpath`
  and `tstamps`. Components are written subcircuit instance by subcircuit instance, as Eeschema writes them
  sheet by sheet in page order: the root first, then each instance followed by the ones inside it,
  in instantiation order. In each, they are sorted by reference in natural order (`R2` before `R10`).
- `nets`: `code` (from 1), `name`, `class` (`"Default"`), and `node`s with `ref`, `pin` (the
  footprint pad number), `pinfunction` (if the pin has a name) and `pintype`. Nets are sorted by
  name in natural order (case-sensitive); nodes by reference and then pad, both in string order
  (as KiCad does).
- `design` has only `source` (if set with `with_source`) and `tool`. No date is written, so the
  output does not change between exports.
- Not written: `libparts`, `libraries`, `datasheet`, `description`, and the `Sheetname` /
  `Sheetfile` properties. Custom fields are written in `fields` only, not repeated as `property`
  (pcbnew reads `fields`).
- Multi-unit parts are one component with all the pins of the symbol and a single `tstamps`
  (Eeschema writes one UUID per unit).

## 5. Errors

Besides the errors of `to_netlist` (`doc/circuits.md` section 6), `to_kicad` reports:

| Error (`CircuitErrorKind`) | Cause |
|---|---|
| `KicadUnsupported` | `kicad()` returns `None` |
| `FootprintMissing` | no footprint assigned |
| `PinInfoMissing` | no `KicadPinInfo` for a pin ID |
| `UnknownPinId` | a `KicadPinInfo` for a pin ID the part does not have |
| `DuplicatePad` | two pins on the same pad |

The output is checked against pcbnew and Eeschema by the tools described in `doc/dev/verifying.md`.
