# Exporting a KiCad Netlist

This document explains how to export a circuit described with cuprite_wire (`doc/circuits.md`) as a
KiCad 9 netlist (`.net`) for pcbnew, and its bill of materials (section 6). See `doc/dev/kicad_netlist_format.md` for the file format itself.
A complete example is in `examples/kicad_rc_filter.rs`
(`cargo run --example kicad_rc_filter > rc_filter.net`).

## 1. Pipeline

```rust
let netlist = circuit             // CircuitBuilder
    .build(&options)              // BuiltCircuit
    .to_netlist()?                // Netlist (doc/circuits.md)
    .to_kicad()?                  // KicadNetlist: KiCad information resolved and checked
    .with_source("my_board.rs");  // optional `source` in the `design` section
netlist.write(&mut file)?;        // or `netlist.to_string()`
```

`to_kicad()` returns `Err(CircuitErrors)` with all errors found (section 5). `with_source` panics
if the source contains a NUL character.

## 2. KiCad information of parts

`Part::kicad()` returns the KiCad information of a part; `None` (the default) makes `to_kicad()`
fail with `KicadUnsupported`. Parts generated by `kicad_part!` fill it from the symbol and the
footprint (`doc/kicad_part_macro.md`). By hand:

```rust
fn kicad(&self) -> Option<KicadPartInfo> {
    Some(KicadPartInfo {
        footprint: Some("Resistor_SMD:R_0603_1608Metric".parse().unwrap()),
        pins: BTreeMap::from([
            ("1".into(), KicadPinInfo::new("1", None, PinType::Passive)),
            ("2".into(), KicadPinInfo::new("2", None, PinType::Passive)),
        ]),
        lib_source: Some("Device:R".parse().unwrap()),
        ..Default::default()   // fields, flags (dnp, exclude_from_bom, exclude_from_board),
                               // datasheet, description, units
    })
}
```

- `KicadPinInfo` gives the pad number (`pin` in the netlist), the pin name (`pinfunction`) and the
  electrical type (`pintype`). `KicadPartInfo::pins` needs exactly one entry per pin ID, and pads
  must be unique within a part.
- A part made from a symbol with several units (a dual op-amp) lists what KiCad appends to the
  reference of each unit in `KicadPartInfo::units` (`["A", "B", "C"]`, from `unit_letters`, or
  the symbol's unit names), and gives each pin its unit with `KicadPinInfo::with_unit` (0, the
  default, for a pin of every unit). The automatic net names then use the reference of the unit
  (`Net-(U1A-OUT)`) as KiCad does; a pin in a unit the part does not have is an error
  (`UnknownPinUnit`).
- `LibId` (`Library:Name`) is checked when it is parsed or created with `LibId::new`.
- An instance can override the value, footprint, fields, flags and SPICE description of its part
  with the methods of `PartExt` (implemented for every part and `Box<dyn Part>`), without writing
  a new part:

  ```rust
  use cuprite_wire::parts::PartExt;

  c.instantiate_part(Resistor0603::new("10k").dnp());
  c.instantiate_part(Resistor0603::new("10k").with_field("MPN", "RC0603FR-0710KL"));
  ```

  `with_value`, `with_footprint`, `with_field` (replaces a field of the part or appends one),
  `dnp`, `exclude_from_bom`, `exclude_from_board` and `with_spice` return an `Overridden`, on
  which they can be chained. The KiCad overrides do not change what is simulated: a DNP part is
  still simulated, and `with_value` does not change the simulated value. `with_spice` replaces the
  SPICE description (`SpicePartInfo`, with pin IDs as in a hand-written part,
  `doc/spice_netlist_usage.md` section 2), e.g. of a part whose model `kicad_part!` cannot convert:

  ```rust
  // An ideal amplifier for the first unit of a dual op-amp without a model (`spice: none`).
  let amp = Lm358Soic::new().with_spice(
      SpicePartInfo::element(SpiceElement::new('E', ["1", "4", "3", "2"], "100k"))
          .with_unused_pins(["5", "6", "7", "8"]),
  );
  ```

  The pins cannot be overridden: they are what the part is (its pin ID constants, the checks
  against the symbol and footprint), and a different pin set is a different part.
- For hand-written parts, whether a pad number exists in the footprint is not checked (it would
  require reading the footprint libraries; `kicad_part!` does it). Use
  `tools/check_netlist_footprints.py` (`doc/dev/verifying.md`).

## 3. UUIDs

pcbnew matches footprints on the board to netlist components by UUID (`tstamps`), so the UUIDs
must not change between exports. cuprite_wire derives them (UUID v5) from the **hierarchical path
and the instance name** of each part (`doc/circuits.md` section 4), never from reference
designators or source locations. The `tstamps` of a `sheetpath` joins the UUIDs of the subcircuit
instances with `/`.

Automatic instance names, and with them the UUIDs, can change when the circuit is edited: see the
note in `doc/circuits.md` section 4.

## 4. Output

- `components`: `ref`, `value` (`~` if empty), `footprint`, `datasheet` and `description` (if set
  and not `~` or empty, as Eeschema omits them), `fields` (if any), `libsource` (if set), value-less `property` flags (`exclude_from_board`, `exclude_from_bom`, `dnp`), `sheetpath`
  and `tstamps`. Components are written subcircuit instance by subcircuit instance, as Eeschema writes them
  sheet by sheet in page order: the root first, then each instance followed by the ones inside it,
  in instantiation order. In each, they are sorted by reference in natural order (`R2` before `R10`).
- `nets`: `code` (from 1), `name`, `class` (`"Default"`), and `node`s with `ref`, `pin` (the
  footprint pad number), `pinfunction` (if the pin has a name) and `pintype` (with the suffix
  `+no_connect` for the only pin of a net marked with `circuit.no_connect`, as KiCad writes a pin
  with a no-connect flag; pcbnew then does not report the pad as unconnected). Nets are sorted by
  name in natural order (case-sensitive); nodes by reference and then pad, both in string order
  (as KiCad does).
- `design` has only `source` (if set with `with_source`) and `tool`. No date is written, so the
  output does not change between exports.
- Not written: `libparts`, `libraries`, the `Footprint` / `Datasheet` / `Description` fields, the
  `description` of `libsource`, and the `Sheetname` / `Sheetfile` properties. Custom fields are written in `fields` only, not repeated as `property`
  (pcbnew reads `fields`).
- Multi-unit parts are one component with all the pins of the symbol, and `tstamps` has a UUID
  for each unit, as Eeschema writes it. The first is the component's UUID (the same as for a
  single unit), which pcbnew takes as the footprint's path; the others are derived from it.

## 5. Errors

Besides the errors of `to_netlist` (`doc/circuits.md` section 6), `to_kicad` reports:

| Error (`CircuitErrorKind`) | Cause |
|---|---|
| `KicadUnsupported` | `kicad()` returns `None` |
| `FootprintMissing` | no footprint assigned |
| `PinInfoMissing` | no `KicadPinInfo` for a pin ID |
| `UnknownPinId` | a `KicadPinInfo` for a pin ID the part does not have |
| `UnknownPinUnit` | a `KicadPinInfo` in a unit that `KicadPartInfo::units` does not have |
| `DuplicatePad` | two pins on the same pad that are not connected inside the part (connected ones are duplicate pins: the pad is written once, with the first of them in `Part::pin_ids`) |
| `KicadNulCharacter` | a NUL character, where KiCad would end the text, in the value, a field name or value, the datasheet, the description, a unit name, or a pin's pad or name |

The output is checked against pcbnew and Eeschema by the tools described in `doc/dev/verifying.md`.

## 6. Bill of materials

`KicadNetlist::bom` makes a bill of materials, written as CSV in the format of
`kicad-cli sch export bom` (`doc/dev/kicad_bom_format.md`):

```rust
use cuprite_wire::kicad::BomOptions;

let bom = netlist.to_kicad()?.bom(&BomOptions::default().with_field("MPN"));
bom.write(&mut file)?;            // or `bom.to_string()`; `bom.rows()` for the data
```

```text
"Refs","Value","Footprint","Qty","DNP","MPN"
"C1,C2","100n","Capacitor_SMD:C_0603_1608Metric","2","",""
"R1-R5","10k","Resistor_SMD:R_0603_1608Metric","5","",""
"X4","custom","Custom:Footprint","1","DNP","A"
```

- Components with `exclude_from_bom` are left out. DNP components are listed in rows of their own,
  marked `DNP` (mark an instance with `part.dnp()`, section 2); `exclude_dnp` leaves them out.
- Components are grouped into one row when all their cells are equal, except the references and
  the quantity (`BomGrouping::Columns`). Add the fields that tell parts apart
  (`with_field("MPN")`), or they are grouped by value and footprint only.
  `group: BomGrouping::None` writes a row per component. `BomGrouping::Fields(vec![..])` groups by
  the given fields, written or not, as kicad-cli's `--group-by`: a cell whose components differ
  lists their values (`1nF,22uF`).
- Three or more consecutive references are written as a range (`R1-R5`). As with kicad-cli,
  `ref_delimiter` and `ref_range_delimiter` change the separators (an empty
  `ref_range_delimiter` lists them all), and `field_delimiter` and `string_delimiter` the CSV
  separator and quote (e.g. `"\t"` and `""` for tab-separated values without quotes).
- The columns (`BomOptions::columns`) can show the references, the value, the footprint, the
  symbol (`LibSource`), the datasheet and the description (`KicadPartInfo::datasheet` /
  `description`, which `kicad_part!` takes from the symbol), the quantity, the DNP flag and any
  part field, with any label.
- Rows are sorted by their first reference in natural order.
