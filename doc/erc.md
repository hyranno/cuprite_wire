# Electrical Rules Check (ERC)

`Netlist::erc` checks a circuit by the electrical types of its pins, following the rules of KiCad 9's
ERC that depend only on the netlist. The checks follow KiCad 9.0's source (`eeschema/erc/erc.cpp`,
`eeschema/connection_graph.cpp`). Rules about schematic drawings (wires, buses, sheets, label
placement, annotation) do not apply, and since one part holds all units of a symbol, neither do
the multi-unit rules.

## 1. Running ERC

```rust
use cuprite_wire::erc::{ErcSettings, check_subcircuit};

let report = circuit
    .build(&options)
    .to_netlist()?                // structural errors (duplicate references, ...) stop here
    .erc(&ErcSettings::default());
report.assert_no_errors();        // or assert_clean(), errors(), warnings(), violations
```

ERC returns an `ErcReport` instead of failing: it holds every violation with its `Severity`
(`Error` or `Warning`; ignored ones are left out). `Display` prints them with traces like the errors
of `to_netlist` (`doc/circuits.md` section 6). The report also holds the warnings of
`to_netlist` (`MultipleNetNames`, `LabelOnlyNet`), so a test only needs to look at the report.

## 2. Pin types

Pin types are those of KiCad (`PinType`: `input`, `output`, `bidirectional`, `tri_state`, `passive`,
`free`, `unspecified`, `power_in`, `power_out`, `open_collector`, `open_emitter`, `no_connect`).
`Part::pin_types` gives them; its default takes them from `Part::kicad`, so parts generated by
`kicad_part!` have the types of their symbols. Pins without a type, such as those of the
simulation-only sources, are treated as `passive`.

## 3. Rules

Each net is checked for:

| Rule | Default | Violation |
|---|---|---|
| `PinToPin` | see below | two pins whose types conflict |
| `PinNotConnected` | error | the only pin of the net (except `no_connect` and `free` pins) |
| `PinNotDriven` | error | an `input` pin on a net without `output`, `power_out`, `passive`, `tri_state` or `bidirectional` pins |
| `PowerPinNotDriven` | error | a net with a `power_in` pin and without a `power_out` pin |
| `NoConnectConnected` | warning | a net marked no-connect with more than one pin |
| `NoConnectDangling` | warning | a no-connect mark on a net without part pins |
| `VirtualPinDangling` | warning | a virtual pin on a net without part pins |
| `SimilarNetNames` | warning | net names differing only in case |
| `MultipleNetNames` | warning | a net with several names (from `to_netlist`) |
| `LabelOnlyNet` | warning | a labeled net without part pins (from `to_netlist`; an error in KiCad) |

Notes:

- On a net with a `power_in` pin, only `power_out` pins count as drivers, and the net is reported
  as `PowerPinNotDriven` (on one of its `power_in` pins) even if it also has `input` pins.
- A no-connect mark silences `PinNotConnected`, `PinNotDriven` and `PowerPinNotDriven` on its net.
- Pins of one part in the same group of `Part::internal_connections` and of the same type are
  treated like KiCad's stacked pins: they never conflict with each other and count as one pin.
- A lone `input` pin is reported both as not connected and as not driven, as KiCad does.

`PinMap` (the pin conflict matrix) gives the severity of connecting two pin types; the default is
KiCad's. Like KiCad, a net reports each conflicting pin once, starting from the pin types KiCad
reports first (`free`, `unspecified`, `passive`, ...); the conflicts of the reported pin are not
reported again. KiCad pairs the pin with the nearest conflicting pin in the drawing; here the pin is
paired with its conflicting pin of the highest severity.

Severities are changed with `ErcSettings`:

```rust
let mut settings = ErcSettings::default().with_severity(ErcRule::PinNotConnected, Severity::Warning);
settings.pin_map.set(PinType::Output, PinType::Output, Severity::Ignore);
```

The severity of `PinToPin` (`Error` by default) is the highest a pin conflict can be: `Warning`
reports the errors of the pin map as warnings, and `Ignore` turns pin conflicts off.

## 4. Marks

Nodes can carry marks seen only by ERC; the exporters ignore them. Like labels, marks attached
inside a subcircuit stay on the nets of the circuit that instantiates it.

| Method | KiCad equivalent | Effect |
|---|---|---|
| `circuit.no_connect(node)` | no-connect flag | the net is intentionally unconnected |
| `circuit.power_flag(node)` | `PWR_FLAG` | a virtual `power_out` pin named `PWR_FLAG` |
| `circuit.virtual_pin(node, pin_type, name)` | - | a pin outside the circuit, e.g. what a connector brings in |
| `circuit.erc_allow(node, rule)` | excluded ERC marker | the violations of `rule` on the net are not reported |

As in KiCad, a supply that enters the board through a connector (a `passive` pin) needs a
`power_flag` for the `power_in` pins on it. Global labels connect nets but are not pins, so a
`GND` label does not drive anything by itself.

`erc_allow` excludes one rule on one net, where `ErcSettings` would change it everywhere:

```rust
circuit.erc_allow(bus, ErcRule::PinToPin);   // outputs connected on purpose
```

`SimilarNetNames` is left out if either of the two nets allows it. Nothing is reported for an
`erc_allow` without violations: a subcircuit may have them when checked alone but not on the
board, or the other way around. The rules about nets without part pins (`NoConnectDangling`,
`VirtualPinDangling`, `LabelOnlyNet`) cannot be allowed; remove the mark or the label instead, or
change their severity.

## 5. Checking a subcircuit

`check_subcircuit` runs ERC on one `SubcircuitGenerator` alone. Its interface nodes have nothing
connected to them, so give each one the pin the circuit around it is expected to connect, in the
generator's interface struct holding `Option<PinType>`:

```rust
let ports = FollowerPorts {
    input: Some(PinType::Output),    // driven from outside
    output: Some(PinType::Input),    // read from outside
    vcc: Some(PinType::PowerOut),    // the supply
    gnd: Some(PinType::PowerOut),
};
check_subcircuit(&Follower, &(), &ports, &ErcSettings::default())?.assert_clean();
```

Each port becomes a virtual pin named `port <name>` (the field name, or the index in an array),
traced to the call of `check_subcircuit`. Nodes given `None` are checked as if nothing were
connected to them.
`check_subcircuit` fails only if the subcircuit cannot be converted to a netlist.
`examples/sensor_frontend/` checks each of its subcircuits this way, and the whole board before
writing its netlist.
